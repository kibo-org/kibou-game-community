# Kibou Game Community

[English](README.md) | 日本語

部屋やクエスト、遊び心のあるアイデアをみんなでつくる、オフライン前提の 3D 村です。
PlayCanvas というゲームエンジンで動きます。登場人物、申請、会話はすべて架空で、
あなたの端末の中だけで完結します。実在のアカウント、Host、宿泊予約、アップロード、
本番 API は一切ありません。

## はじめての方へ

プログラミングも GitHub も初めてでも大丈夫です。まずは
[はじめの10分 / Your First Change](START_HERE.md) を読んでみてください。
コードを書かずに [相談だけする](https://github.com/kibo-org/kibou-game-community/issues/new?template=help.yml)
こともできます。

このリポジトリでよく出てくる言葉を先に説明します。

| 言葉 | 意味 |
| --- | --- |
| リポジトリ | このプロジェクトのファイル一式と変更履歴の置き場所 |
| Issue | GitHub 上の相談・提案スレッド。アイデアだけの投稿も歓迎 |
| Fork | リポジトリを自分のアカウントにコピーすること。招待は不要 |
| PR（Pull Request） | 自分の変更を本家に取り込んでもらうための提案 |
| 管理者（Maintainer） | PR を確認して取り込む担当者 |
| CI | PR に対して自動で動く検査。外部参加者の分は管理者の承認後に動く |

## 参加するには

招待や本家への書き込み権限は必要ありません。流れはこうです。

1. Issue でやりたいことを相談する
2. リポジトリを自分のアカウントに Fork する
3. 小さな変更を加えて PR を開く
4. 管理者が最終版を確認してから merge する

外部参加者の CI は管理者の承認が必要です。「承認待ち」の表示はエラーでも合格でもなく、
通常の状態です。

詳しくは [CONTRIBUTING.md](CONTRIBUTING.md)、[COMMUNITY_TASKS.md](COMMUNITY_TASKS.md)、
そして手順を丁寧に書いた [開発ガイド（日本語）](DEVELOPMENT_GUIDE_JA.md) を読んでください。
ソースコード、ドキュメント、投稿は英語または日本語を使います。

Issue、PR、コミットの作者情報は誰でも見られます。commit には GitHub の noreply
メールアドレスを使ってください（設定方法は [START_HERE.md](START_HERE.md) にあります）。

## 手元で動かす

Node.js 22 以上が必要です。見慣れない変更を動かす前にコードを読んでください。
開発用のフォルダは、本番の認証情報や個人ファイルとは分けておきます。

```sh
npm ci --ignore-scripts
npm run dev
```

ブラウザで http://127.0.0.1:5175 を開きます。サーバーは自分のパソコンの中だけで動き、
外部には公開されません。HMR（自動再読み込み）は無効なので、編集後はページを
再読み込みしてください。3D の中を正確に歩き回れなくても、「告示板（Noticeboard）」と
「Next step」から各場所へ行けます。マウス、タッチ、キーボードのどれでも同じ操作ができます。

変更を確認するコマンドは次の4つです。PR を出す前に実行します。

```sh
npm run check:boundary
npm run typecheck
npm test
npm run build
```

PlayCanvas はバージョン 2.20.6 に固定しています。専用の lockfile でツール一式も固定済みです。
`--ignore-scripts` はインストール時のスクリプトを止めるだけで、テストやビルドツールの
実行まで止めるものではありません。エンジンのバンドルが大きいことは既知の性能課題です。
実機の iPhone Safari や支援技術での受け入れ確認は、ソース公開とは別に行います。
実際に行った検査と制限事項は [PUBLICATION_AUDIT.md](PUBLICATION_AUDIT.md) を見てください。

## 何かつくってみる

| ファイル | 中身 |
| --- | --- |
| `src/fixtures.ts` | 架空の場所、家のルール、会話、クエストの文章 |
| `src/world.ts` | プリミティブで組んだオリジナルの 3D の部屋、木、架空のキャラクター |
| `src/scene.ts` | PlayCanvas のライフサイクル、カメラ、移動、操作 |
| `src/demoAdapter.ts` | ローカルのクエスト・申請シミュレーション。実際の予約は絶対にしない |
| `src/contracts.ts` | 参加用のインターフェースと、上限付きの保存データ形式 |
| `src/style.css` | レスポンシブレイアウトとアクセシビリティ用のスタイル |
| `src/ui.ts` | プレーンテキストで DOM を扱う補助関数と操作エラーの処理 |

最初は、Issue で合意した1つのタスクから始めてください。たとえば `src/fixtures.ts` の
クエストの文章を一文だけ良くする、といった小さな変更がおすすめです。

このデモが保存するのは、上限付きの架空の進捗だけです。保存先は
`kibou-community-fiction:v1` というキー1つで、リセットはこのキーだけを削除します。
読み込めない保存データは、明示的なリセットが成功するまでそのまま保護されます。
名前、メールアドレス、本人確認書類、自由入力のチャットは一切求めません。
ローカルで「承認」されても、現実の権限は何も付きません。

## レビューの境界

Fork → 作業ブランチ → main 向け PR → 自動検査 → 別の管理者によるレビュー → 管理者が merge。
この順番は固定です。

次のものは絶対に投稿しないでください。

- 個人情報、認証情報（Token、パスワード、API キー）
- 本番のコードやデータ
- 出どころやライセンスが不明な素材

参加者に本番の権限が付与されることはありません。このリポジトリから自動でホスティングや
本番デプロイが行われることもありません。また、このリポジトリをログイン済みの
Website と同じオリジンで配信してはいけません。

レビューを通った変更は、別の PR を通じて非公開の正式ゲームに取り込まれることがあります。
詳しくは [PRODUCTION_ADOPTION.md](PRODUCTION_ADOPTION.md) を読んでください。同じエンジンを
使っていても、ID、保存領域、権限、互換性が共有されるわけではありません。
